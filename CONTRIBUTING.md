# Contributing

Small, focused changes are welcome.

1. Open an issue before a large feature or architecture change.
2. Never include real family photos, credentials, private hostnames or personal data.
3. Keep route handlers thin and put reusable business rules under `features/`.
4. Prefer a direct implementation over a framework or abstraction without a current use case.
5. Run `npm run check` and `npm run build` before opening a pull request.

Bug fixes should include a regression test. New behavior should update the README or the relevant document under `docs/`.
